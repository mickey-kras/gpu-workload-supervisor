# v0.1.5 operator notes

## Release verification behavior

Workload release uses user systemd lifecycle state and cgroup v2 evidence instead
of a total GPU memory threshold. Stopped workloads must be inactive/dead with an
empty configured cgroup subtree (or a removed subtree). Missing, malformed or
unreadable evidence and mismatched manager metadata fail closed. Unrelated GPU
allocations do not affect this release check. Cgroup evidence proves processes
have exited; it does not prove asynchronous driver cleanup has finished.

Live-media unload is not supported by a trustworthy completion verifier. An HTTP
success response alone is insufficient, so this path fails closed. Use
`-media-stop-mode stop-service`, or explicitly stop media before recovery. The UI
is unavailable while its service is stopped.

## Configuration migration

Remove `-release-max-used-mib`, including explicit `=0`; the flag is rejected.
Configure `-text-cgroup` and `-media-cgroup` consistently for every controller
sharing the state store. Use the canonical, distinct, non-overlapping paths of
the actual user systemd units within the host `/sys/fs/cgroup` hierarchy. The
active user manager root slice must strictly contain both paths. Nested mounts
and container mappings are unsupported.

Optional `-text-required-mib`, `-media-required-mib` and
`-capacity-headroom-mib` checks separately assess pre-start capacity. They do not
reserve memory or replace release verification. Repair a capacity failure before
explicit recovery. Boot reconciliation does not resume interrupted work or take
control away from user ownership.

## Rollback and deployment limits

Do not downgrade in place against migrated state or mix controller/proxy versions
sharing a database. Keep a consistent pre-upgrade SQLite backup and matching
configuration/binaries. Stop proxies, automation and workloads before restoring
state; rotate the restored fence using `restore-state` before reconciliation and
before restarting proxies. See [the restore procedure](https://github.com/mickey-kras/gpu-workload-supervisor/blob/v0.1.5/docs/RESTORING.md). A restore
cannot stop work already executing outside the proxy, and ownership recovery
never restarts stopped user work automatically.

Artifacts target Linux amd64 and arm64 and include `gpu-mode` and
`gpu-workload-proxy`. Publication alone does not certify a host deployment,
runtime-specific execution/completion, or host acceptance tests. Qualification
requires the verified source commit, successful release jobs and actual artifact
digests to be recorded separately; these notes do not assert those steps have
already completed.
